## What this means for ORCH

**Write confinement: holds.** Probe 2 attempted an absolute path outside the working root and the
file was never created. `-s workspace-write` confines writes to `-C` plus any `--add-dir`.

**Egress: denied by default, and the flag is not broken here.** Probe 3 fetched nothing. Probe 4
turned `sandbox_workspace_write.network_access=true` on and the fetch *succeeded* — so GH #10390
does **not** reproduce on this machine, at codex-cli 0.147.0.

That is worse news than the bug reproducing would have been. If the flag were broken, egress would
be denied no matter what any config said. Because it works, default-deny egress is a **choice that
must keep being made** on every invocation, and a stray `-c` or an edited `~/.codex/config.toml`
silently restores the open network. The build scripts must pass sandbox flags explicitly and never
inherit them.

**Reads are not confined. This is the finding that matters.** Probe 5 read a file outside the
working root and returned its contents verbatim. A `workspace-write` run can read anything the user
can read: `~/.aws/credentials`, `~/.ssh`, `.env` files, and — directly relevant to this repository —
`~/.claude/projects/**` transcripts, which can contain live credentials in cleartext.

So the sandbox gives us two of the three boundaries:

| Boundary | Enforced by the sandbox? |
|---|---|
| Write scope | **Yes** |
| Network egress | **Yes, by default** — but re-openable, so pass it explicitly every run |
| Read scope | **No** |

The consequence is that **reading a secret is possible and exfiltrating it is not** — the egress
denial is what makes the open read survivable, and the two controls are load-bearing together.
Neither one alone is sufficient, which is the layered-architecture claim from the source article
arriving as a measurement rather than an assertion.

It also means `AGENTS.md` rule 4 — never read, print or copy credentials — is not belt-and-braces.
On reads it is the *only* control, and it is enforced by nothing but instruction. Treat any Codex
run that touches transcript fixtures as a run that can see a live key, and never let one write its
output anywhere that leaves this machine.

**Verdict for the plan:** specs 002 and 003 may proceed under `-s workspace-write`, with sandbox
flags passed explicitly on every invocation and never inherited from config.
